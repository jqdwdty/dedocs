Single-file source for .docx

Exact package fidelity, readable authoring, no server.

Dedocs turns a Word document package into one inspectable text file, keeps the exact OOXML package as ground truth, and layers semantic commands on top so humans and AI can edit with intent.

Why it exists

OOXML is exact. It is not a good working surface.

Raw .docx

Good for Word. Bad for review, AI context, and deterministic source control.

Unpacked OOXML

Exact, but scattered across many files with archive plumbing and noisy diffs.

Dedocs

One file, exact package parts, generated guides, and explicit semantic transforms.

Architecture

Three layers, one source of truth.

1

Core package

The exact .docx package is flattened into explicit part blocks. XML stays UTF-8. Binary stays base64.

2

Guides

Generated summaries expose structure fast, but they never become the source of truth.

3

Transforms

Authoring commands compile onto package parts and fail loudly when anchors no longer match.

    Workflow

    Use it like source, not like a zip archive.

    1. Decompile

    dedocs decompile input.docx output.dedocs

    2. Edit

    edit guides, transforms, or raw package payloads

    3. Normalize

    dedocs normalize output.dedocs

    4. Compile + verify

    dedocs compile output.dedocs rebuilt.docx
dedocs verify input.docx rebuilt.docx

    Dedocs is a static package and static site. No runtime server. No hidden backend.
